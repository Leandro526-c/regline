The NIST reference problems

NIST, the US metrology institute, publishes reference datasets (“StRD”) to test statistical software. For nonlinear regression, each problem gives the measurements, the formula, two starting points (the first far from the solution, the second closer) and the certified values of the parameters and their standard deviations, to 11 digits. The problems range from “lower” to “higher” difficulty.

The formulas were typed as in the NIST document, as a student would, then fitted by Regline without any special setting. The table gives the number of correct digits on the worst parameter, for the values and for the standard deviations, and the reliability light shown by Regline.

The reliability light

Since version 4.1, every fit has a light: green “Stable calculation”, orange “To check” or red “Doubtful”. Regline quietly reruns the fit from other starting points and checks the parameters and residuals. It never changes the value shown: it only adds an explanation and suggests what to do.

What is not perfect

  • MGH17 and Lanczos1, start 1: from this deliberately very distant start, Regline does not find the right solution. The red “Doubtful” light turns on (“Two equally good solutions” or “Parameters not identifiable”). From NIST's second start, the values are correct.
  • Lanczos1, start 2: the parameters are correct to 10 digits, but the standard deviations only to 3. This problem has differences of about 10⁻¹¹ between the measurements and the curve, at the limit of what a computer can calculate; most software fails here.
  • ENSO: 5 correct digits, plenty for a lab.
  • A cautious light: on 8 correct runs (Lanczos2, Lanczos3, Bennett5, and Lanczos1 and MGH17 from the second start), the light is still red. These problems are built so that parameters compensate each other almost perfectly, and Regline says so. One alarm too many is better than a wrong result in silence.
  • BoxBOD, start 1: from this start, the fit alone does not succeed. Regline finds the right solution from another start, shows it and flags it in orange (“Initial values corrected”).

Are the stated uncertainties honest?

A “1σ” uncertainty should contain the true value about 68 times out of 100. To check this, we simulate measurements with known noise, fit them, and count how often the true value falls within the interval stated by Regline.

Redo the check

You can redo any of these tests: download a dataset from the NIST website, paste the x and y columns into Regline, type the formula and starting values from the document into a fit with your own formula, and compare with the certified values.

These checks are run by Regline's author with automatic scripts, rerun for every major version. They do not replace an independent audit, and do not spare you from checking that the chosen model suits your experiment.
